Don’t install

Interview assignments often arrive as a full GitHub repo. The README usually says to run npm install. That can run hidden code on your laptop.

RepoSafety is a Cursor command. It reads the repository first — without installing or running it — and tells you whether to install. You still decide. A clean report is not a promise that the repo is safe.

The usual first steps are the risky ones.

You get a take-home. You clone it. You install packages. You start the app. Maybe you ask an AI coding assistant to work in the folder. Any of those steps can run code you have not read.

  1. Clone the repo This part is usually fine.
  2. Install packages This can run extra scripts the moment you type it.
  3. Start the app Starting the dev server can load the trap even when install scripts look clean.
  4. Let an AI agent loose in it An assistant that “just installs dependencies” is running the same commands you would.

RepoSafety sits after clone, before install.

Three steps. Then you decide.

  1. 1

    Clone. Stop.

    Copy the take-home to your machine. Do not run npm install, yarn, pnpm, pip, or the README’s “getting started” commands yet.

  2. 2

    Run the command in Cursor

    Open the folder and type /interview-repo-safety in Agent chat. The skill only reads files. It does not install the project to inspect it.

  3. 3

    Read the verdict

    You get one answer: safe to install, review first, or do not install — plus a short report. You choose what happens next.

What the skill actually does

Every row was checked against the public /interview-repo-safety skill. A tick means the skill performs that check. A cross means it does not — even if an older version of this page implied it.

The skill does this

  • ✓
    Reads the repo without installing or running it

    Looks at files only. No npm install, no tests, no app start, no Docker of the take-home itself.

  • ✓
    Checks package lists, including extra “dev” packages

    Reads package.json and lock files. Also looks at Python, Rust, Go, and other manifest files when they are there. Packages your packages depend on are included when a lock file can be read.

  • ✓
    Checks scripts that run when you install

    Flags preinstall, postinstall, prepare, and similar keys — plus app scripts that would load a trap on npm run dev.

  • ✓
    Checks Git hooks and editor auto-run

    Looks at .git/hooks, VS Code / Cursor tasks, IntelliJ configs, and Dev Container commands that run when you open the folder.

  • ✓
    Looks for secrets, and hides the values

    Checks .npmrc, .env files, CI config, and git history. The report names the type, file, and severity. It does not print the secret.

  • ✓
    Looks for code that calls a remote server and then runs the reply

    Static search for things like eval, new Function, hidden loaders, and hardcoded IPs. It records the addresses. It does not download the payload.

  • ✓
    Asks whether the packages fit the assignment

    If a wallet take-home ships a random animation plugin, that mismatch is a finding — not automatic proof of malware, but a reason to stop.

  • ✓
    Looks for lookalike package names

    Simple name checks (think lodash vs lodahs). This is a heuristic, not a full commercial database.

  • ✓
    Writes one report with one verdict

    Exactly one of: safe to install, review first, or do not install — plus high / medium / low confidence. No made-up “safety score.”

  • ✓
    Can install later in Docker, not on your laptop — only if you ask

    After a “safe” or “review” verdict, you can request a sandbox run. The box sees only the repo folder. The internet is blocked except registry.npmjs.org until you name another host. A “do not install” verdict refuses this unless you clearly ask to observe.

The skill does not do this

  • ✕
    Prove the repository is safe

    The skill says this outright. A clean report means “nothing obvious turned up,” not “this is safe.”

  • ✕
    Bundle Sonatype or Opsera scanning

    Those tools are used only if you already have them in Cursor. The skill does not install them. The published example ran without them.

  • ✕
    Replace other security tools you already use

    The skill has its own checks. It is not a new dashboard for Sonatype, Opsera, or npm audit.

  • ✕
    Catch every hidden trick

    Heavily obfuscated code and behavior that only appears after install can be missed. File reading cannot see runtime.

  • ✕
    See inside encrypted downloads in Docker

    The sandbox logs which hosts were contacted and how many bytes moved. It does not decrypt HTTPS.

  • ✕
    Replace a throwaway virtual machine

    If the project needs your home folder, sudo, Docker-on-Docker, or an open network, the skill will say you need a disposable VM. It will not loosen the sandbox.

  • ✕
    Scan a GitHub URL from this website

    This site explains the skill. The check runs in your editor, on a repo you already cloned.

This is what it caught on a real take-home.

A coding-interview repo presented as “Proof of Dev.” The README said to run npm install && npm run dev. That was enough to trigger the trap. The skill said do not install before anything ran.

In plain English

The assignment did not need an animation plugin. That plugin pulled in a second package. The second package calls a raw IP address and runs whatever comes back. Following the README is enough.

If you already ran it

Treat that machine as compromised. The skill cannot undo an install that already happened. Do not run this project in the sandbox either — the verdict was do not install.

Install the skill, then run it on the take-home.

This is a Cursor skill (it also works in Claude Code). It is not a website you paste a GitHub link into. 

git clone https://github.com/naval200/interview-repo-safety.git
cd interview-repo-safety
mkdir -p ~/.cursor/skills
ln -s "$(pwd)/skills/interview-repo-safety" ~/.cursor/skills/interview-repo-safety
  1. 1

    Restart Agent chat

    So Cursor picks up the new skill.

  2. 2

    Clone the take-home. Do not install.

    Open that folder in Cursor.

  3. 3

    Run /interview-repo-safety

    Read the verdict before you follow the README.

Docker is only needed later, if you ask to install inside the sandbox. Other agents can use npx skills add naval200/interview-repo-safety.
